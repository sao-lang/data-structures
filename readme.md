## 数据结构学习计划

基本包括：固定数组  动态数组 单向链表  双向链表 单向循环链表  双向循环链表  栈 队列 循环队列 双端队列  哈希表 Trie(字典树) 二叉树 二叉搜索树 AVL树 最小堆 最大堆 图 BFS/DFS遍历 并查集 跳表 红黑树(Red-Black Tree) 线段树 树状数组(Fenwick Tree) 布隆过滤器(Bloom Filter) LRU缓存 后缀数组 KD树

## 数据结构学习指南

### 通用学习步骤

1. **理解概念**：先理解数据结构的定义、特点和核心思想
2. **画图理解**：通过画图来可视化数据结构的操作过程
3. **手动实现**：用至少一种编程语言手动实现一遍
4. **分析复杂度**：理解各种操作的时间和空间复杂度
5. **刷题练习**：通过 LeetCode 等平台的题目来巩固
6. **实际应用**：思考在实际项目中如何应用

## 数据结构详细说明

### 1. 固定数组 (Fixed Array)

**特点**：
- 连续内存存储，通过索引直接访问元素，时间复杂度 O(1)
- 大小在创建时必须确定，创建后不可改变
- 内存分配一次性完成，无需动态扩容
- 空间效率高，没有浪费的预留空间

**使用场景**：
- 元素数量已知且不变的场景
- 需要极限性能和内存控制的场景（如图形处理、嵌入式系统）
- 底层系统编程
- 静态数据表

---

### 2. 动态数组 (Dynamic Array / ArrayList)

**特点**：
- 连续内存存储，通过索引直接访问元素，时间复杂度 O(1)
- 大小可以动态调整，创建时只需指定初始容量
- 容量不足时自动扩容，通常扩容为原来的 1.5-2 倍
- 扩容时需要重新分配内存并迁移数据，时间复杂度 O(n)

**使用场景**：
- 元素数量不确定的场景
- 需要灵活存储和易用性的场景（如用户输入列表、集合容器）
- 频繁随机访问，但插入删除主要在末尾的场景
- 大多数应用程序的通用集合需求

---

### 3. 单向链表 (Singly Linked List)

**特点**：
- 非连续内存存储，通过指针/引用连接节点
- 每个节点只包含 next 指针，只能单向遍历
- 内存占用较少（每个节点少一个指针）
- 在已知位置后插入删除简单，时间复杂度 O(1)
- 查找和删除已知节点需要从头遍历，时间复杂度 O(n)

**使用场景**：
- 栈的实现
- 节省内存的单向遍历场景
- 不需要反向遍历的简单链表需求
- 哈希表冲突解决（链式寻址）

---

### 4. 双向链表 (Doubly Linked List)

**特点**：
- 非连续内存存储，每个节点同时包含 prev 和 next 指针
- 可以从前往后和从后往前双向遍历
- 内存占用较多（每个节点多一个指针）
- 可以直接通过节点本身进行删除操作
- 在已知位置前后插入都简单，时间复杂度 O(1)

**使用场景**：
- 双端队列的实现
- 需要频繁删除操作的场景
- LRU 缓存实现
- 需要双向遍历的场景
- 编辑器的撤销/重做功能

---

### 5. 单向循环链表 (Circular Singly Linked List)

**特点**：
- 单向链表的变体，首尾节点相连形成环形
- 只包含 next 指针
- 可以循环从任意节点开始遍历
- 删除操作需要遍历到节点或找到前驱

**使用场景**：
- 循环队列的实现
- 约瑟夫环问题
- 环形缓冲区
- 轮流分配资源的场景
- 定时器管理

---

### 6. 双向循环链表 (Circular Doubly Linked List)

**特点**：
- 双向链表的变体，首尾节点相连形成环形
- 同时包含 prev 和 next 指针
- 可以循环双向遍历
- 可以直接通过节点本身进行删除操作
- 在已知位置前后插入都简单

**使用场景**：
- 循环缓冲
- LRU 缓存（更高效的实现）
- 需要循环双向遍历的场景
- 内存管理（空闲链表）

---

### 7. 栈 (Stack)

**特点**：
- LIFO（后进先出）原则
- 只能在栈顶进行插入（Push）和删除（Pop）操作
- 可以基于数组或链表实现
- 操作时间复杂度均为 O(1)
- 支持查看栈顶元素（Peek/Top）

**使用场景**：
- 函数调用栈（递归实现）
- 表达式求值（逆波兰表达式）
- 括号匹配检查
- 浏览器历史记录（后退功能）
- 撤销操作（Undo）
- 深度优先搜索（DFS）

---

### 8. 队列 (Queue)

**特点**：
- FIFO（先进先出）原则
- 只能在队尾插入（Enqueue），队头删除（Dequeue）
- 可以基于数组或链表实现
- 操作时间复杂度均为 O(1)
- 支持查看队头元素（Peek/Front）

**使用场景**：
- 任务队列（如消息队列、打印队列）
- 广度优先搜索（BFS）
- 生产者-消费者模式
- 缓冲区（如键盘输入缓冲区）
- 线程池任务调度

---

### 9. 循环队列 (Circular Queue)

**特点**：
- 数组实现的队列优化版本
- 利用取模运算实现环形结构，避免"假满"现象
- 充分利用数组空间
- 操作时间复杂度 O(1)
- 需要使用 front 和 rear 指针以及取模运算

**使用场景**：
- 固定容量的缓冲区
- 任务调度器
- 网络数据包缓冲
- 滑动窗口算法
- 生产者-消费者模式（固定容量）

---

### 10. 双端队列 (Deque - Double Ended Queue)

**特点**：
- 两端都可以进行插入和删除操作
- 结合了栈和队列的特性
- 可以基于数组或双向链表实现
- 操作时间复杂度 O(1)
- 支持在队头和队尾进行 Add/Remove/Get 操作

**使用场景**：
- 滑动窗口最大值/最小值
- 回文检查
- 需要两端操作的场景
- 某些图算法优化
- 既需要栈又需要队列的场景

---

### 11. 哈希表 (Hash Table)

**特点**：
- 通过哈希函数将键映射到数组索引
- 平均查找、插入、删除时间复杂度 O(1)
- 冲突解决：链式寻址（Separate Chaining）或开放寻址（Open Addressing）
- 空间换时间的典型数据结构
- 最坏情况下时间复杂度退化为 O(n)

**使用场景**：
- 键值对存储（如数据库索引、缓存）
- 频率统计（如词频统计）
- 去重操作
- 快速查找场景（如用户认证、路由表）
- 符号表实现

---

### 12. Trie (字典树/前缀树)

**特点**：
- 树形结构，用于存储字符串
- 每个节点代表一个字符
- 共享前缀，节省空间
- 前缀查询效率高，时间复杂度 O(k)，k 为前缀长度
- 可以按字典序输出所有单词

**使用场景**：
- 自动补全（如搜索引擎、输入法）
- 拼写检查
- 前缀匹配
- IP 路由最长前缀匹配
- 字符串排序
- 联系人搜索

---

### 13. 二叉树 (Binary Tree)

**特点**：
- 每个节点最多有两个子节点（左子节点和右子节点）
- 遍历方式：前序、中序、后序、层序
- 结构灵活，但最坏情况下退化为链表
- 高度为 h 的二叉树最多有 2^h - 1 个节点
- 第 i 层最多有 2^(i-1) 个节点

**使用场景**：
- 表达式树
- 哈夫曼编码树
- 基础树形结构学习
- 决策树
- 语法分析树

---

### 14. 二叉搜索树 (Binary Search Tree, BST)

**特点**：
- 左子树所有节点值 < 根节点值 < 右子树所有节点值
- 平均查找、插入、删除时间复杂度 O(log n)
- 最坏情况下退化为链表，时间复杂度 O(n)
- 中序遍历可得到有序序列
- 支持范围查询

**使用场景**：
- 动态查找表
- 有序数据的维护
- 范围查询
- 符号表实现
- 需要保持数据有序的场景

---

### 15. AVL 树

**特点**：
- 自平衡二叉搜索树
- 左右子树高度差不超过 1（平衡因子）
- 查找、插入、删除时间复杂度均为 O(log n)
- 严格平衡，查找效率高，但插入删除需要较多旋转操作
- 每次插入/删除后最多需要 2 次旋转

**使用场景**：
- 查找密集型应用
- 读多写少的场景
- 需要保证最坏情况性能的场景
- 内存数据库索引
- 实时系统

---

### 16. 红黑树 (Red-Black Tree)

**特点**：
- 自平衡二叉搜索树
- 通过颜色规则和旋转保持近似平衡
- 查找、插入、删除时间复杂度均为 O(log n)
- 平衡要求不如 AVL 严格，但插入删除效率更高
- 每次插入/删除后最多需要 3 次旋转
- 从根到叶子的最长路径不超过最短路径的两倍

**使用场景**：
- 通用有序集合/映射（如 C++ STL map/set、Java TreeMap）
- 插入删除频繁的场景
- Linux 内核进程调度
- 内存管理
- 定时器管理

---

### 17. 最小堆 (Min Heap)

**特点**：
- 完全二叉树结构
- 父节点值 ≤ 子节点值，根节点为最小值
- 插入和提取最小值时间复杂度 O(log n)
- 通常用数组实现
- 支持查看最小值（Peek），时间复杂度 O(1)

**使用场景**：
- 优先队列（最小优先级）
- Dijkstra 最短路径算法
- Prim 最小生成树算法
- Top K 最小元素问题
- 任务调度（按优先级升序）

---

### 18. 最大堆 (Max Heap)

**特点**：
- 完全二叉树结构
- 父节点值 ≥ 子节点值，根节点为最大值
- 插入和提取最大值时间复杂度 O(log n)
- 通常用数组实现
- 支持查看最大值（Peek），时间复杂度 O(1)

**使用场景**：
- 优先队列（最大优先级）
- 堆排序
- Top K 最大元素问题
- 任务调度（按优先级降序）
- 中位数维护

---

### 19. 图 (Graph)

**特点**：
- 由顶点（Vertex）和边（Edge）组成
- 表示方式：邻接矩阵、邻接表
- 有向图/无向图、加权图/无权图
- 灵活表示各种关系网络
- 支持各种图算法（遍历、最短路径、最小生成树等）

**使用场景**：
- 社交网络（好友关系）
- 地图导航（路径规划）
- 网络拓扑（路由器连接）
- 推荐系统
- 编译器（依赖分析）
- 电路设计

---

### 20. BFS/DFS 遍历 (Breadth-First Search / Depth-First Search)

**特点**：
- BFS：按层遍历，使用队列实现，保证最短路径（无权图）
- DFS：深入探索后回溯，使用栈或递归实现
- BFS 空间复杂度通常较高，需要存储所有层
- DFS 内存需求较小，只存储一条路径
- 都是图的基本遍历算法

**使用场景**：
- BFS：无权图最短路径、社交网络好友推荐、层级遍历、网页爬虫
- DFS：拓扑排序、连通性检测、迷宫求解、回溯问题、生成所有排列组合
- 图的遍历和搜索
- 树的遍历

---

### 21. 并查集 (Union-Find / Disjoint Set Union, DSU)

**特点**：
- 用于处理动态连通性问题
- 主要操作：Find（查找根节点）、Union（合并两个集合）
- 路径压缩 + 按秩合并优化后，操作近乎 O(1)
- 空间复杂度 O(n)
- 实现简单，效率极高

**使用场景**：
- 图的连通性检测
- 最小生成树（Kruskal 算法）
- 朋友圈/社交网络分析
- 动态连通性问题
- 图像处理（区域合并）
- 编译器（类型等价性）

---

### 22. 跳表 (Skip List)

**特点**：
- 多层链表结构，通过随机化实现平衡
- 平均查找、插入、删除时间复杂度 O(log n)
- 最坏时间复杂度 O(n)
- 实现比平衡树简单
- 支持范围查询
- 并发友好
- 空间复杂度 O(n log n)

**使用场景**：
- Redis Sorted Set
- 替代平衡树
- 有序集合/映射
- 数据库索引
- LevelDB / RocksDB
- 并发数据结构

---

### 23. 线段树 (Segment Tree)

**特点**：
- 用于区间查询和区间更新
- 完全二叉树结构
- 查询和更新时间复杂度 O(log n)
- 支持多种区间操作（求和、最大值、最小值、乘积等）
- 空间复杂度 O(4n)
- 实现复杂度较高

**使用场景**：
- 区间统计问题
- 动态规划优化
- 竞赛编程
- 数组区间更新/查询
- 直方图最大面积
- 天际线问题

---

### 24. 树状数组 (Fenwick Tree / Binary Indexed Tree, BIT)

**特点**：
- 用于前缀和查询和单点更新
- 二进制索引实现
- 查询和更新时间复杂度 O(log n)
- 空间复杂度 O(n)
- 实现比线段树简单
- 主要支持前缀和，扩展可支持区间更新

**使用场景**：
- 前缀和问题
- 逆序对计数
- 频率统计
- 动态前缀和查询
- 更简洁的线段树替代方案
- 竞赛编程

---

### 25. 布隆过滤器 (Bloom Filter)

**特点**：
- 概率型数据结构，用于判断元素是否存在
- 多个哈希函数 + 位数组
- 可能误报（False Positive），但不会漏报（False Negative）
- 空间效率极高，不需要存储实际元素
- 不支持删除操作（计数布隆过滤器除外）
- 添加和查询时间复杂度 O(k)，k 为哈希函数个数

**使用场景**：
- 缓存穿透防护
- 网络爬虫 URL 去重
- 数据库查询优化（先过滤再查询）
- 垃圾邮件过滤
- 分布式系统（如 Bigtable、Cassandra、HBase）
- 比特币钱包

---

### 26. LRU 缓存 (Least Recently Used)

**特点**：
- 最近最少使用淘汰策略
- 哈希表 + 双向链表实现
- Get 和 Put 操作时间复杂度 O(1)
- 容量满时自动淘汰最久未使用的元素
- 最近使用的元素移到头部
- 最久未使用的元素在尾部

**使用场景**：
- 浏览器缓存
- 数据库查询缓存
- 操作系统页面置换算法
- 内存管理
- CDN 缓存
- Redis LRU 策略

---

### 27. 后缀数组 (Suffix Array)

**特点**：
- 字符串所有后缀的排序数组
- 构建时间复杂度 O(n log n)（基于倍增算法或诱导排序）
- 查询时间复杂度 O(log n)（二分查找）
- 空间效率高于后缀树
- 可以配合 LCP（最长公共前缀）数组使用
- 实现相对简洁

**使用场景**：
- 字符串匹配
- 最长公共子串
- 生物信息学（DNA/RNA 序列分析）
- 文本压缩
- 后缀自动机构建
- 搜索引擎

---

### 28. KD 树 (K-Dimensional Tree)

**特点**：
- 用于 k 维空间点的划分和搜索
- 二叉树结构，每层按不同维度划分
- 平均最近邻查询时间复杂度 O(log n)
- 最坏时间复杂度 O(n)
- 适合低维空间（k ≤ 20）
- 支持范围查询
- 构建时间复杂度 O(n log n)

**使用场景**：
- 空间数据库
- 计算机视觉（特征点匹配）
- 机器学习（k 近邻算法）
- 地理信息系统（GIS）
- 碰撞检测
- 游戏开发（3D空间搜索）

## 数组类型对比

| 特征         | 固定数组 (FixedArray)       | 动态数组 (DynamicArray/ArrayList)        |
|--------------|-----------------------------|------------------------------------------|
| 定义时机     | 大小在创建时必须确定。      | 大小可以不确定，或者只确定一个初始容量。 |
| 大小改变     | 不可变。一旦创建，容量终生不变。 | 可变。可以根据需要自动增长或（在某些实现中）缩减。 |
| 容量管理     | 无需管理。容量是固定的。     | 自动管理。容量不足时，会进行扩容操作。   |
| 插入操作     | 快速，但如果数组已满，则插入失败。 | 通常快速 (O(1))，但如果需要扩容，则会变成耗时的操作 (O(n))。 |
| 内存分配     | 一次性分配所需的全部连续内存空间。 | 初始分配小块内存，容量不足时重新分配更大的内存块，并将旧数据迁移到新块。 |
| 空间效率     | 高（没有浪费的预留空间）。  | 较低（为了未来增长，通常会预留一部分未使用的空间）。 |
| 底层实现     | 通常直接映射到硬件提供的原生数组。 | 通常是在代码层面封装了一个原生数组，并管理其容量和数据迁移。 |
| 适用场景     | 元素数量已知且不变；需要极限性能和内存控制的场景（如底层系统编程、图形处理）。 | 元素数量不确定；需要灵活存储和易用性的场景（如用户输入列表、集合容器）。 |

## 链表类型对比

| 特征         | 单向链表 (Singly Linked List) | 双向链表 (Doubly Linked List) | 单向循环链表 (Circular Singly) | 双向循环链表 (Circular Doubly) |
|--------------|--------------------------------|--------------------------------|--------------------------------|--------------------------------|
| 节点结构     | 只包含 next 指针              | 同时包含 prev 和 next 指针     | 只包含 next 指针，首尾相连     | 同时包含 prev 和 next 指针，首尾相连 |
| 内存占用     | 较少（每个节点少一个指针）     | 较多（每个节点多一个指针）     | 较少                          | 较多                          |
| 遍历方向     | 只能从前往后                  | 可以从前往后和从后往前        | 可以循环从任意节点开始遍历     | 可以循环双向遍历              |
| 删除操作     | 需要知道前驱节点或从头遍历    | 可以直接通过节点本身删除      | 删除需要遍历到节点或找前驱     | 可以直接通过节点本身删除      |
| 插入操作     | 在已知位置后插入简单          | 在已知位置前后插入都简单      | 在已知位置后插入简单          | 在已知位置前后插入都简单      |
| 空间开销     | 较小                          | 较大                          | 较小                          | 较大                          |
| 适用场景     | 单向遍历、栈实现、节省内存    | 需要双向遍历、双端队列、频繁删除操作 | 循环队列、约瑟夫环问题 | 循环缓冲、LRU 缓存 |

## 栈与队列类型对比

| 特征         | 栈 (Stack)                    | 队列 (Queue)                  |
|--------------|-------------------------------|-------------------------------|
| 操作原则     | LIFO (后进先出)               | FIFO (先进先出)               |
| 插入位置     | 顶部 (Top)                    | 尾部 (Rear)                   |
| 删除位置     | 顶部 (Top)                    | 头部 (Front)                  |
| 主要操作     | Push, Pop, Peek               | Enqueue, Dequeue, Peek        |
| 常见应用     | 函数调用栈、表达式求值、撤销操作 | 任务队列、消息队列、广度优先搜索 |
| 底层实现     | 数组或链表                    | 数组或链表                    |

## 队列优化类型对比

| 特征         | 普通队列 (Simple Queue)       | 循环队列 (Circular Queue)      | 双端队列 (Deque)             |
|--------------|-------------------------------|-------------------------------|-------------------------------|
| 空间利用     | 可能出现"假满"现象            | 充分利用数组空间              | 灵活，可在两端操作            |
| 操作限制     | 只能一端插入一端删除          | 只能一端插入一端删除          | 两端都可以插入和删除          |
| 时间复杂度   | O(1)                          | O(1)                          | O(1)                          |
| 实现复杂度   | 简单                          | 中等（需要取模运算）          | 中等                          |
| 适用场景     | 一般队列需求                  | 固定容量的队列、缓冲区        | 需要两端操作、滑动窗口        |

## 哈希表冲突解决对比

| 特征         | 链式寻址 (Separate Chaining)  | 开放寻址 (Open Addressing)    |
|--------------|-------------------------------|-------------------------------|
| 冲突处理     | 使用链表存储冲突元素          | 寻找下一个空槽位              |
| 内存使用     | 需要额外空间存储链表指针      | 所有元素都在数组中            |
| 缓存性能     | 较差（链表节点分散）          | 较好（数组连续内存）          |
| 删除操作     | 简单（直接删除链表节点）      | 复杂（需要标记或重新哈希）    |
| 负载因子     | 可以超过 1                    | 通常小于 0.7                  |
| 适用场景     | 负载因子高、频繁删除          | 内存紧张、追求缓存性能        |

## 树结构类型对比

| 特征         | 二叉树 (Binary Tree)          | 二叉搜索树 (BST)              | AVL 树 (平衡二叉树)           | 红黑树 (Red-Black Tree)       |
|--------------|-------------------------------|-------------------------------|-------------------------------|-------------------------------|
| 节点约束     | 最多两个子节点                | 左 < 父 < 右                  | 左右子树高度差 ≤ 1           | 红黑节点颜色规则              |
| 查找时间     | O(n) 最坏情况                 | O(log n) 平均，O(n) 最坏      | O(log n) 最坏                 | O(log n) 最坏                 |
| 插入时间     | O(n) 最坏情况                 | O(log n) 平均，O(n) 最坏      | O(log n) 最坏                 | O(log n) 最坏                 |
| 删除时间     | O(n) 最坏情况                 | O(log n) 平均，O(n) 最坏      | O(log n) 最坏                 | O(log n) 最坏                 |
| 旋转操作     | 无                            | 无                            | 每次插入/删除后最多 2 次旋转 | 每次插入/删除后最多 3 次旋转 |
| 平衡严格度   | 无                            | 无                            | 严格平衡（高度差 ≤ 1）        | 近似平衡（黑色高度相等）      |
| 实现复杂度   | 简单                          | 中等                          | 复杂                          | 很复杂                        |
| 适用场景     | 基础树结构、表达式树          | 动态查找、有序数据            | 查找密集、读多写少            | 插入删除频繁、通用场景（C++ STL、Java TreeMap） |

## 堆类型对比

| 特征         | 最小堆 (Min Heap)             | 最大堆 (Max Heap)             |
|--------------|-------------------------------|-------------------------------|
| 根节点       | 最小值                        | 最大值                        |
| 父节点关系   | 父 ≤ 子                       | 父 ≥ 子                       |
| 主要操作     | Extract Min, Insert           | Extract Max, Insert           |
| 常见应用     | 优先队列、Dijkstra 算法       | 优先队列、堆排序              |
| 时间复杂度   | 插入 O(log n)，提取 O(log n)  | 插入 O(log n)，提取 O(log n)  |

## 图表示方式对比

| 特征         | 邻接矩阵 (Adjacency Matrix)   | 邻接表 (Adjacency List)       |
|--------------|-------------------------------|-------------------------------|
| 空间复杂度   | O(V²)                         | O(V + E)                      |
| 边查询       | O(1)                          | O(degree(V))                  |
| 添加/删除边  | O(1)                          | O(1) 或 O(degree(V))          |
| 遍历邻居     | O(V)                          | O(degree(V))                  |
| 适用场景     | 稠密图、需要快速边查询        | 稀疏图、节省内存              |
| 内存效率     | 稀疏图时浪费空间              | 高效利用空间                  |

## 图遍历算法对比

| 特征         | 广度优先搜索 (BFS)            | 深度优先搜索 (DFS)            |
|--------------|-------------------------------|-------------------------------|
| 数据结构     | 队列 (Queue)                  | 栈 (Stack) 或递归             |
| 遍历顺序     | 按层遍历                      | 深入探索后回溯                |
| 最短路径     | 可以找到无权图的最短路径      | 不保证最短路径                |
| 空间复杂度   | O(V)                          | O(V)                          |
| 适用场景     | 最短路径、社交网络好友推荐    | 拓扑排序、连通性检测、迷宫求解 |
| 实现方式     | 迭代                          | 递归或迭代                    |

## 高级数据结构对比

| 特征         | 并查集 (Union-Find)           | 跳表 (Skip List)              |
|--------------|-------------------------------|-------------------------------|
| 主要操作     | Union, Find                   | Search, Insert, Delete        |
| 时间复杂度   | 近乎 O(1) (路径压缩 + 按秩合并) | O(log n) 平均                 |
| 空间复杂度   | O(n)                          | O(n log n)                    |
| 适用场景     | 图的连通性、最小生成树        | 替代平衡树、有序集合          |
| 实现复杂度   | 简单                          | 中等（需要随机化）            |

## Trie (字典树) 对比

| 特征         | Trie 树                        | 哈希表 (Hash Table)            |
|--------------|-------------------------------|-------------------------------|
| 空间复杂度   | O(n * k)，n 为单词数，k 为平均长度 | O(n)                         |
| 前缀查询     | O(k)，k 为前缀长度            | 无法高效前缀查询，需要遍历所有键 |
| 排序输出     | 可以按字典序输出所有单词      | 无序输出                      |
| 单词长度     | 单词越长，Trie 越省空间       | 与单词长度关系不大            |
| 适用场景     | 自动补全、拼写检查、前缀匹配  | 通用查找、键值对存储          |
| 实现复杂度   | 中等                          | 简单                          |

## 图遍历对比

| 特征         | BFS (广度优先)                 | DFS (深度优先)                 |
|--------------|-------------------------------|-------------------------------|
| 数据结构     | 队列                          | 栈 (递归或迭代)               |
| 空间复杂度   | O(V)                          | O(V) (递归栈或显式栈)         |
| 最短路径     | 可以找到无权图的最短路径      | 不保证最短路径                |
| 内存需求     | 通常需要更多内存（存储所有层） | 通常内存需求较小（只存储一条路径） |
| 适用场景     | 最短路径、社交网络好友推荐、层级遍历 | 拓扑排序、连通性检测、迷宫求解、回溯问题 |
| 实现方式     | 迭代                          | 递归或迭代                    |

## 并查集 (Union-Find) 特点

| 操作         | 时间复杂度 (路径压缩 + 按秩合并) |
|--------------|----------------------------------|
| Find (查找)  | 近乎 O(1) (α(n)，逆阿克曼函数)   |
| Union (合并) | 近乎 O(1)                        |
| Connected (连通) | 近乎 O(1)                     |
| 空间复杂度   | O(n)                             |

**适用场景**：
- 图的连通性检测
- 最小生成树 (Kruskal 算法)
- 动态连通性问题
- 朋友圈、社交网络分析

## 跳表 (Skip List) 特点

| 操作         | 平均时间复杂度 | 最坏时间复杂度 |
|--------------|----------------|----------------|
| Search (查找) | O(log n)       | O(n)           |
| Insert (插入) | O(log n)       | O(n)           |
| Delete (删除) | O(log n)       | O(n)           |
| 空间复杂度   | O(n log n)     | O(n log n)     |

**优势**：
- 实现比平衡树简单
- 可以支持范围查询
- 并发友好
- 可以动态调整

**适用场景**：
- 替代平衡树 (AVL、红黑树)
- 有序集合/映射
- Redis Sorted Set
- 数据库索引

## 线段树与树状数组对比

| 特征         | 线段树 (Segment Tree)         | 树状数组 (Fenwick Tree)       |
|--------------|-------------------------------|-------------------------------|
| 核心功能     | 区间查询（和、最大、最小）、区间更新 | 前缀和查询、单点更新          |
| 时间复杂度   | O(log n) 查询和更新           | O(log n) 查询和更新           |
| 空间复杂度   | O(4n)                         | O(n)                          |
| 实现复杂度   | 较高（需要处理多个区间）      | 较低（二进制索引简单）        |
| 灵活性       | 高（支持多种区间操作）        | 中（主要支持前缀和）          |
| 适用场景     | 区间统计、动态规划优化、竞赛题 | 前缀和问题、逆序对计数、更简洁的实现 |

## 布隆过滤器 (Bloom Filter) 特点

| 操作         | 时间复杂度 | 特点                          |
|--------------|------------|-------------------------------|
| 添加元素     | O(k)，k 为哈希函数个数 | 可能误报，不会漏报            |
| 查询元素     | O(k)       | 空间效率极高                  |
| 删除元素     | 不支持（标准实现） | 计数布隆过滤器支持删除        |

**优势**：
- 空间效率远高于哈希表
- 查询和插入速度极快
- 不需要存储实际元素

**适用场景**：
- 缓存穿透防护
- 网络爬虫URL去重
- 数据库查询优化
- 垃圾邮件过滤

## LRU 缓存特点

| 操作         | 时间复杂度 | 实现方式                      |
|--------------|------------|-------------------------------|
| Get (获取)   | O(1)       | 哈希表 + 双向链表             |
| Put (插入)   | O(1)       | 头部插入、尾部淘汰            |

**核心思想**：
- 最近使用的元素保留
- 最久未使用的元素淘汰
- 容量满时自动淘汰

**适用场景**：
- 浏览器缓存
- 数据库查询缓存
- 页面置换算法
- 内存管理

## 后缀数组 (Suffix Array) 特点

| 操作         | 时间复杂度 | 说明                          |
|--------------|------------|-------------------------------|
| 构建         | O(n log n) | 基于倍增算法或诱导排序        |
| 查询         | O(log n)   | 二分查找                      |

**优势**：
- 空间效率高于后缀树
- 可以解决多种字符串问题
- 实现相对简洁

**适用场景**：
- 字符串匹配
- 最长公共子串
- 生物信息学（DNA序列分析）
- 文本压缩

## KD 树 (K-Dimensional Tree) 特点

| 操作         | 平均时间复杂度 | 最坏时间复杂度 |
|--------------|----------------|----------------|
| 构建         | O(n log n)     | O(n²)          |
| 插入         | O(log n)       | O(n)           |
| 删除         | O(log n)       | O(n)           |
| 最近邻查询   | O(log n)       | O(n)           |

**优势**：
- 适合低维空间搜索
- 可以进行范围查询
- 空间效率较高

**适用场景**：
- 空间数据库
- 计算机视觉（特征点匹配）
- 机器学习（k近邻算法）
- 地理信息系统
